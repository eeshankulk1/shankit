# Framework audit — August 2026

Full-read audit of both Python packages, the TypeScript client, codegen, CI,
docs, and examples at HEAD (`5011ac7`), with one deep pass per subsystem plus
an independent review of the core loop and of the public-API diff across the
recent refactor series (`6913037..HEAD`). Every finding was verified against
the source before inclusion (many empirically, in the project venv); items
already documented as deliberate in `docs/design.md` §14 or
`docs/deferred-improvements.md` are not re-reported.

**Baseline:** all gates are green at HEAD — 193 tests pass, ruff clean,
pyright clean, TS drift check clean, 15/15 TS tests pass.

Severity: **MAJOR** — a real consumer hits it in normal use and the failure
is run-killing, silent, or misleading. **minor** — real but edge-cased or a
DX/robustness issue. Design gaps and doc drift are labeled as such.

---

## 1. Priority list

Ranked by (likelihood a real consumer hits it) × (badness when they do):

1. **Anthropic converter 400s on empty assistant turns** — the same bug
   already diagnosed and fixed for OpenAI in `c6d1770`, left unfixed on the
   Anthropic side (§3.1).
2. **No SSE heartbeat** — any run with a slow tool call gets killed by
   default proxy idle timeouts, and the TS client renders the half-answer as
   final with no error (§7.1, §7.4).
3. **A raising scorer crashes the entire eval run** — and `llm_judge` makes
   real model calls, so a judge rate-limit kills an expensive run (§6.9).
4. **MCP sessions: one transport failure bricks the source forever**, and
   lazy connect is structurally incompatible with the real MCP SDK's cancel
   scopes (§4.5, §4.6).
5. **Durability assumes exactly one well-behaved driver per thread** — no
   CAS/claim in the Checkpointer contract (double-resume double-fires side
   effects), `run()` silently clobbers interrupted threads, and crashed
   threads are undiscoverable (§5.1–5.3).
6. **A checkpointered network exposed via `as_tool()` fails on every call**,
   swallowed into a generic error — the docs advertise exactly this
   combination (§5.6).
7. **`sse_stream(errors="emit")` swallows unexpected exceptions with zero
   logging**, defeating the loop's own emit-then-re-raise design (§7.2).
8. **`@tool` silently drops unknown/misspelled arguments** — a hallucinated
   parameter is discarded with no corrective signal to the model (§4.1).
9. **`@shankit/client` doesn't work on React Native without polyfills** —
   directly relevant to the mobile app (§7.5).
10. **Codegen silently mis-generates future field types** (enums → empty
    interfaces, nested unions → `unknown`) while `--check` stays green
    (§7.6).

Cross-cutting: **no version bump or changelog has accompanied any of the
recent contract changes** (`.text` semantics, `ModelError`, scorer haystack,
forced first-pass output) — both packages still say `0.1.0`. Pre-publication
this is process debt, not damage, but it is exactly what will hurt the app +
mobile app once they pin versions (§8).

## 2. Core loop (`agent.py`)

- **minor — uniform-error-contract hole for duck-typed sources.**
  `agent.py:649-651`: a source returning anything other than `str`/
  `ToolResult` (`None`, a dict) reaches `_cap_result` *outside* the
  `try` → raw `AttributeError` escapes, cancels sibling tool tasks, and
  kills the run instead of coming back as a sanitized `is_error` result.
- **design gap — no streaming structured run.** `stream()` hardcodes
  `output_type=None`; `run(on_event=)` surfaces steps/sources/usage but
  never text deltas (it calls `complete()`). A surface that wants live text
  *and* a typed deliverable — a skill with live narration — cannot be built.
- **design gap — failed runs lose their accounting.** `MaxIterationsError`,
  `OutputValidationError`, and `ModelError` from `run()` carry no
  usage/trajectory; tokens spent on a failed run are invisible unless the
  caller wired `on_event`. Billing/observability breaks exactly when things
  go wrong.
- **minor — multiple `final_result` calls in one turn**: the last silently
  wins (`agent.py:503-528`).
- **minor — output-tool validation error text is not capped** by
  `max_tool_result_chars` (`agent.py:520-527`); a pathological payload
  echoes an unbounded ValidationError back into the conversation.
- **minor — cancelled sibling tool tasks are not awaited** after `.cancel()`
  (`agent.py:556-559`); cancellation isn't guaranteed complete before the
  exception propagates, and "exception was never retrieved" warnings are
  possible.
- **doc drift — no dedup exists anywhere.** design §3.4 says the `as_tool`
  seam absorbed throu's consult machinery "routing, dedup, sanitized
  failures, token accounting"; there is no dedup in the package (verified),
  and repeated tool calls duplicate `Source` entries on the stream/result.
- **minor — history leniency is thin.** `coerce_message` surfaces a raw
  pydantic `ValidationError` for `role: "system"` / OpenAI-style
  `role: "tool"` dicts — the most likely malformed history a chat app sends
  — instead of a `ShankitError` naming the accepted shape.
- **design gap — text-only boundary.** `Message` content is text/tool blocks
  only; `prompt` is `str`. No image input. With a mobile app dogfooding the
  framework, multimodal input is the most likely near-term ask; the design
  record should take a position (even "not yet").

## 3. Models + messages

1. **MAJOR — Anthropic converter serializes empty assistant turns; the API
   rejects them with a non-retryable 400.** `models/anthropic.py:124` dumps
   messages verbatim. An empty model pass (refusal; or a pass whose only
   blocks were thinking/server-tool blocks, which `parse_message` drops) is
   appended as `Message(role="assistant", content=[])`, followed by the
   structured-output nudge — so it is not final, and the next request 400s;
   the run dies as a non-retryable `ModelError`. The identical scenario was
   found and fixed **for OpenAI only** in `c6d1770`
   (`openai.py:201-207` sends `""` instead). Same 400 also arises from
   caller history via `coerce_message({"role": "assistant", "content": ""})`.
   Fix: mirror the OpenAI patch in `build_kwargs`.
2. **minor — `refusal` / `model_context_window_exceeded` /
   `content_filter` stop reasons flatten to `"other"`** and are treated as
   success (`anthropic.py:25,164`, `openai.py:26`): a refusal becomes an
   empty-string "successful" deliverable with no signal.
3. **minor — OpenAI stream accumulator assumes first-party behavior**
   (`openai.py:96-100`): tool-call `name` fragments overwrite instead of
   append, and a `None` index merges parallel calls into one garbage call.
   Fine on api.openai.com; real for the OpenAI-compatible servers the
   `base_url` parameter invites (vLLM, proxies).
4. **minor — abandoned/failed OpenAI streams leak the HTTP response**
   (`openai.py:77-102`): the SDK `AsyncStream` is never closed except by
   exhaustion (the Anthropic client uses `async with`; the OpenAI one
   doesn't).
5. **minor — `_map_error`'s lazy `import anthropic`/`import openai` in the
   error path** can replace the real error with `ImportError` when a client
   was injected but the SDK isn't importable (`anthropic.py:107`,
   `openai.py:127`).
6. **minor — registry globals aren't thread-safe** (`registry.py:28-57`),
   `register_provider` evicts cached clients without closing them, and
   `aclose()` closes injected clients the caller owns.
7. Positive: the `ModelError` mapping is clean — order matches the SDK
   hierarchies, BaseExceptions pass through, `__cause__` chained, no
   secrets in messages, and no path was found where a raw SDK exception
   escapes the shipped clients.

## 4. Tool sources + connectors

1. **MAJOR — `@tool` silently drops unknown argument names**
   (`tools/local.py:56`): the generated args model defaults to
   `extra="ignore"`, so a hallucinated/misspelled parameter is discarded
   with defaults filling in — `send_email(recipient=...)` against a tool
   declaring `to: str = ""` sends to nobody with no error. `extra="forbid"`
   surfaced as `ToolError` would give the model a corrective signal.
2. **MAJOR — positional-only parameters pass decoration and then crash on
   every call** (`local.py:84-87` vs `63-65`): schema generates fine,
   `call()` uses `fn(**kwargs)` → sanitized "failed unexpectedly" on 100%
   of calls, with no decoration-time signal.
3. **minor — `@tool` edge cases**: callables without `__name__`
   (`functools.partial`, callable objects) crash with a bare
   `AttributeError` even when `name=` is given; double-wrapping discards a
   custom name; a lambda becomes tool `"<lambda>"` (provider 400 far from
   the cause); instance methods put `self` in the model-facing schema;
   missing annotations silently become untyped `{}`; a parameter named
   `model_config` crashes `create_model` opaquely.
4. **minor — `is_tool_source` accepts a class object** (`tools/base.py:84-88`):
   `Agent(tools=[MySource])` (missing `()`) is accepted and fails later,
   confusingly.
5. **MAJOR — MCP: a dead session is never invalidated**
   (`tools/mcp.py:116-119`): nothing resets `_session` on transport
   failure, so one server crash means every future run fails with
   "failed unexpectedly" until the app manually calls `aclose()` — which the
   loop never does.
6. **MAJOR — MCP lazy connect is unusable with the real SDK.** The SDK's
   stdio/http clients enter anyio cancel scopes that must exit in the
   entering task; the loop always drives the source from ephemeral child
   tasks (`asyncio.gather` for `list_tools`, `ensure_future` for execute),
   so the docstring's "you own calling `aclose()` from the same task" is
   unsatisfiable — `aclose()` raises `RuntimeError: Attempted to exit cancel
   scope in a different task`. The fake-SDK tests structurally can't catch
   this. Fix: own a background task for the session, or document lazy mode
   as unsupported.
7. **minor — MCP content fidelity**: image/resource-only results become
   `""` with no marker; `structuredContent` ignored; unknown tool names
   surface as sanitized noise instead of the base contract's
   `ToolNotFoundError` (`base.py:80` promise, unimplemented).
8. **minor — CompositeToolSource route drift**: with context-dependent
   catalogs, `_routes` is last-writer-wins with no ownership-change
   warning (`aggregate.py:42-47`); removed sources are never evicted from
   routes, so apps hot-swapping `composite.sources` keep routing to removed
   sources (a quiet behavior change of `c6d1770`); the collision error is a
   raw `ValueError`, not a `ShankitError`.
9. **Composio, all minor**: a `user_id=lambda ctx: ctx["user_id"]` extractor
   with `context=None` (the loop default) raises an unhandled `TypeError`
   with no hint of the real problem; the cross-tenant ownership guard fails
   *open* when the vendor payload omits the user field
   (`composio.py:271-274` — for a security guard, fail closed or log);
   `successful` defaults to `True` for unrecognized response shapes
   (`composio.py:204` — a renamed flag makes every failure look like
   success); `initiate` never validates `auth_config_id` against
   `self.toolkit`.
10. Positive: the seam is genuinely uniform (nothing special-cases a source
    type); context opacity holds; the Composio tools-cache tenancy claim was
    re-verified and is correct (catalog is API-key-scoped); the
    `skip_version_check` and result-cap implementations are correct and
    well-tested.

## 5. Durability + experimental graph

1. **MAJOR — no atomicity primitive in the Checkpointer contract.**
   `durability/base.py:54-67` is blind upsert/load/delete — no
   compare-and-set, no claim/lease. `resume()`/`recover()` are load →
   check-status → drive (`graph.py:138-149,176-196`): a double-submitted
   approval UI or two workers both resume the same interrupted thread and
   **the consequential action fires twice**. No store implementation can
   fix this; the contract lacks the primitive. `docs/durability.md:96-98`
   actively advertises the risky topology ("hours later, from another
   process").
2. **MAJOR — crashed threads are undiscoverable.** No `list`/`scan(status=)`
   on the contract, so the documented recovery story ("after a crash, call
   `recover(thread_id)`") requires every deployment to keep a parallel
   thread registry outside the checkpointer.
3. **MAJOR — `run()` silently clobbers an existing thread** regardless of
   status (`graph.py:111-125`): re-running the shipped example after killing
   it at the approval prompt destroys the pending interrupted checkpoint.
4. **MAJOR (experimental) — a checkpointered network via `as_tool()` fails
   on every call.** `_NetworkToolSource.execute` (`graph.py:329`) calls
   `network.run()` without `thread_id`, which `run()` rejects when a
   checkpointer is attached (`graph.py:119-123`); the blanket
   `except Exception` turns it into a generic "could not complete the task".
   `docs/durability.md:81-83` advertises the combination right beside a
   checkpointered example.
5. **MAJOR (experimental) — network usage is unaccounted everywhere**:
   `agent_step` keeps only `result.output` (`graph.py:369-375`),
   `NetworkResult` has no usage field, and the network tool source returns
   `ToolResult` without `usage`/`sources`/`artifacts`/`truncated` — in
   direct contrast to `_AgentToolSource` (`agent.py:750-756`) and the
   `sum(UsageEvents) == DoneEvent.usage` invariant of design §14.10. Cost
   dashboards silently undercount.
6. **minor** — JSON round-trip silently coerces state types (`datetime` →
   `str`, `tuple` → `list`), so a router that works on the fresh run raises
   only on the resumed run; no network identity on checkpoints (resuming a
   thread with the wrong network runs a foreign router over the state);
   `max_steps` resets per resume (not a thread-lifetime bound);
   `SqliteCheckpointer.__init__` does blocking sqlite I/O on the event
   loop; writer contention surfaces as raw `sqlite3.OperationalError`
   (which then strands the `in_flight` marker); a checkpointer-less
   interrupt is a dead end (`resume()` refuses, no in-memory path);
   `run()` shallow-copies state (nested structures alias the caller's
   input); no checkpoint-schema versioning.
7. Positive: the single-writer happy path is genuinely solid — the
   write-ahead `in_flight` design is correct and atomic at the SQLite
   statement level, snapshot semantics are enforced and tested, and the
   resume/recover error taxonomy is thorough. The weakness is a single
   theme: the contract assumes exactly one well-behaved driver per thread
   while the docs sell a multi-process story.

## 6. File-first definitions + evals

1. **MAJOR — an unmatched brace in a prompt body escapes the error contract**
   (`files/render.py:29` via `loader.py:125`): prose like
   `Return JSON like { this }` makes `load_agent()` raise a bare
   `ValueError: expected '}' before end of string` — no `AgentFileError`,
   no path, no `{{` hint.
2. **MAJOR (doc drift) — an `Agent` inside a *list* tool reference is not
   adapted via `.as_tool()`** (`loader.py:101-107` vs
   `docs/file-first.md:82-84`): the promised auto-adaptation only handles a
   directly-resolved Agent; list entries fall through to
   `_normalize_tools`'s `TypeError`, whose advice ("call `.as_tool()`") a
   file author cannot follow.
3. **minor — `output_schema` rejects generic aliases the constructor
   accepts** (`loader.py:117`): `isinstance(resolved, type)` is False for
   `list[Item]`, breaking the "identical Agent, not a lossy projection"
   promise.
4. **minor — placeholder validation gaps** (`render.py:31-35`): pure-digit
   `{0}` passes load and crashes at render; no identifier check, so a
   spacing typo becomes a bizarre required context key; JSON in a body fails
   with messages that never mention the `{{` escape.
5. **minor — registry**: silent collision overwrite on process-global
   state, no `unregister`/`clear` (test pollution hazard);
   falsy-but-present `name:`/`model:` values silently fall back to
   stem/default; a UTF-8 BOM fails a valid file with a misleading error
   (`loader.py:181` — use `utf-8-sig`).
6. **doc gap — the trust model is unstated**: `tools: [os:system]` loads
   cleanly and exposes `os.system` to the model. Legitimate design
   (import refs are code), but `file-first.md` should say "agent files are
   code; load only trusted files."
7. **doc drift — Claude Code mirroring over-promises**: CC's `tools` key is
   a comma-separated string; shankit rejects it (good error, wrong claim).
8. **MAJOR — a raising scorer crashes the entire evaluation**
   (`evals/runner.py:85`): scoring sits outside the per-case `try`, so one
   scorer exception propagates through `gather`, abandoning all completed
   and in-flight cases. Not exotic: `llm_judge` makes real model calls — a
   judge rate-limit (`ModelError`) or exhausted retries kills a possibly
   expensive run. `docs/evals.md`'s "never a crash of the whole evaluation"
   only holds for the *run* half.
9. **MAJOR — `dump_str` uses `ensure_ascii=True` for non-BaseModel values**
   (`_serialize.py:23`): `output_contains("Zürich")` silently fails against
   dict/list outputs (`Zürich`) while passing for pydantic outputs —
   and the same escaping garbles non-English sub-agent results fed to
   parent models (`agent.py:738`) and wastes tokens. One-flag fix.
10. **minor — scorer silent-wrong results**: `output_contains()` with no
    `expected` searches for the literal string `"None"` and can pass
    garbage; `exact_match` normalizes only the output side, so a pydantic
    `expected` always fails against an identical output;
    `_JudgeVerdict.score` is unconstrained (a "9 out of 10" judge yields
    `value=9.0, passed=True`); `Case` silently ignores unknown JSONL keys
    (`"expcted"` loads as no expectation) with poor error locality on
    malformed lines; `EvalReport.mean("typo")` returns `0.0`.
11. **minor — `default_step_describer` output is ugly for real tool names**
    (`observe.py:38-39`): `mcp__github__search_code` →
    `"Mcp  github  search code"` — and this string is the product-facing
    narration the framework headlines.
12. **minor — `OUTPUT_TOOL_NAME` isn't exported at the root** even though
    runtime errors tell users to avoid colliding with `"final_result"`.

## 7. Events / SSE / TypeScript client / codegen / CI / packaging

1. **MAJOR — no heartbeat/keepalive on `sse_stream`** (`sse.py:35-56`): a
   60s+ tool call (normal for sub-agents; design §14.14 describes exactly
   such a run) emits nothing on the wire, and default proxy idle timeouts
   (nginx 60s) kill the connection mid-run. The TS parser already handles
   comment lines, so the client is ready for a heartbeat the server never
   sends.
2. **MAJOR — `errors="emit"` swallows unexpected exceptions with no
   logging** (`sse.py:50-56`): `Agent.stream` yields the sanitized event
   and *re-raises* precisely so bugs stay visible; `sse_stream` then eats
   the exception silently. A framework bug surfaces in production only as
   "The run failed unexpectedly." with no server-side traceback. One
   `logger.exception` fixes it.
3. **minor — SSE hygiene**: no `finally: await events.aclose()` (the
   aclose/disconnect path leaves the inner generator to GC, delaying tool
   cancellation); `errors` is an unvalidated `str` (a typo silently means
   "emit"); the docs recipe sets no `Cache-Control`/`X-Accel-Buffering`
   headers, so default nginx buffering freezes the stream.
4. **minor — TS: silent truncation on clean connection drop**
   (`sse.ts:84-99`): a proxy-killed stream (see 7.1) ends *normally*; a
   `for await` UI renders the half-answer as final. Only `collectRun`
   detects the missing terminal event. Also: no runtime shape guard on
   parsed JSON; the non-2xx path leaks the connection and discards the
   error body; malformed-event errors embed up to 200 chars of payload.
5. **MAJOR (platform) — `@shankit/client` is unusable on React Native
   without polyfills** (`index.ts:50-52`): RN fetch has no
   `response.body` ReadableStream, so the mobile app hits
   "stream response has no body" on every call. Needs at least a README
   caveat (it currently claims "any runtime with fetch and Web Streams"),
   or an XHR/text fallback.
6. **MAJOR (latent) — codegen silently mis-generates unhandled schema
   shapes**: an `Enum` field becomes an *empty interface*; a nested
   discriminated union (`oneOf`) becomes `unknown`; tuples, typed dicts,
   and aliased fields degrade silently — all while `--check` stays green.
   Make generation *fail* on unrecognized shapes.
7. **minor — the cross-language "cannot drift" story has one hole**: the TS
   wire-format test fixture is hand-maintained bytes with a non-runnable
   regeneration comment; CI checks *types*, not wire bytes. A golden test
   generating fixtures from the Python side would close it.
8. **minor — CI/packaging**: `package.json` claims Node >=18 but CI tests
   only 20/22 (and 18 is EOL); `examples/07_ts_consumer.ts` is compiled by
   nothing and will rot; pyright doesn't cover `tests/`; no publish
   workflow; byte-exact TS drift check is coupled to the locked pydantic
   version (contributors on other versions get spurious diffs). Extras,
   `py.typed`, and version floors all verified correct.
9. Positive: the TS SSE parser is genuinely spec-solid (multi-line data,
   comments, CRLF split across chunks, TextDecoder streaming, cancel on
   early exit — all traced and tested); there is currently **zero** type
   drift between `events.py` and `events.generated.ts`; the CI gates match
   the README's claims.

## 8. Backward compatibility for apps on shankit

Verified across `6913037..HEAD` (and the earlier hardening series): the
public Python surface is additive at the signature level — no renames or
removals. The hazards are *semantic*:

1. **`DoneEvent.text` / `RunResult.text` changed meaning** (final pass →
   full transcript). Deliberate (§14.10), but any consumer rendering
   `done.text` as "the answer" now shows interim narration. Shipped with no
   version bump.
2. **`run()` no longer raises provider SDK exceptions** — downstream
   `except anthropic.RateLimitError` retry code silently stops matching;
   migrate to `ModelError.retryable`.
3. **Scorer semantics shifted twice**: haystack moved from `.text` to
   `.output`, and serialization from `str()` to `json.dumps` (double
   quotes + `\uXXXX` escapes) — downstream eval suites can flip results
   silently.
4. **Structured no-tool agents now force `final_result` on pass 1**
   (`da75a7a`): custom `ModelClient`s that mishandle `ForcedTool`, and any
   recorded/scripted tests expecting a text-first pass, change behavior.
   Note `llm_judge`'s judge agent is exactly this shape.
5. **New `ArtifactEvent` flows to old clients**: switch-based consumers are
   safe, but an exhaustive `default: throw` consumer crashes. The "unknown
   event types are additive — ignore them" policy should be written down in
   the client README.
6. **Connector behavior changes** (`0d53a3b`): `check_status`/adopt can now
   raise `PermissionError` for cross-tenant access; unknown/`INACTIVE`
   statuses report `failed` instead of `pending`; with a warm
   `tools_cache_ttl`, a vendor-side tool added mid-TTL is refused until
   expiry.
7. **`Interrupt` became keyword-only** (pydantic alias, `dfc0a1a`) —
   positional construction breaks (allowed under the experimental flag).
8. **Process**: both packages have sat at `0.1.0` through all of the above,
   with no changelog. Before throu/mobile pin real versions, adopt semver
   bumps + a CHANGELOG so "pre-transcript-semantics" is expressible in a
   dependency range.

## 9. Test-gap summary (highest value first)

1. **`AnthropicModel.stream` has zero coverage** (the OpenAI accumulator is
   well-tested; the Anthropic path not at all).
2. **Durability concurrency: zero coverage** — concurrent save/resume/
   recover, SQLite contention; graph is never tested against
   `SqliteCheckpointer` (hiding the JSON-coercion divergence).
3. **A raising scorer / judge-failure path** in evals (would have caught
   §6.8).
4. **MCP against the real SDK** — an integration test over a trivial stdio
   server would catch both session-lifecycle majors; fakes structurally
   cannot.
5. **Cross-language golden wire test** (Python-generated fixtures consumed
   by the TS tests).
6. **Empty-assistant-turn through each converter** (would have caught
   §3.1); `default_stream_from_complete` never exercised; `coerce_message`
   with block-list dicts and failure shapes.
7. **File-loader edge cases**: lone braces, BOM, malformed YAML, list refs
   containing an Agent, registry collisions.
8. **`as_tool()` + checkpointer; resume with the wrong network; crash after
   step completion but before post-step save** (the conservative
   false-ambiguity window).

## Overall read

The framework is in better shape than most alpha codebases: the seam design
is disciplined and genuinely uniform, the recent hardening series fixed real
bugs, the gates are green, and the decision record is unusually honest. The
findings cluster into four themes:

1. **Asymmetric hardening** — several bugs were found and fixed on one side
   of a symmetric boundary and not the other (empty turns: OpenAI fixed,
   Anthropic not; usage propagation: agent-as-tool yes, network-as-tool no;
   error contract: tools sanitized, `sse_stream` unlogged).
2. **The unhappy path loses information** — failed runs lose usage, crashed
   evals lose all results, swallowed exceptions lose tracebacks, dead
   streams look like clean completions.
3. **Durability's contract is thinner than its documentation** — the
   multi-process, hours-later story needs a claim/CAS primitive and
   enumeration before it's real.
4. **Silent degradation over loud failure** in the generative surfaces —
   `@tool` schema generation, codegen, scorers, and the file loader all
   have paths that accept bad input and mis-behave later instead of
   erroring at the source.

None of these invalidate the design; nearly all are contained fixes. The
priority list in §1 is ordered so that the first five items cover everything
a production consumer is likely to hit this quarter.
